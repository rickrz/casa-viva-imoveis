Banco de dados

O site da Casa Viva guarda tudo em um PostgreSQL na nuvem (Neon), normalizado até a 3ª Forma Normal. O navegador nunca fala com o banco direto: ele chama a API Flask (/api/...) e a API é quem executa o SQL. Esta página reúne o DER, as tabelas, as restrições de integridade e as consultas usadas na apresentação.

Como o site conversa com o banco

Toda a persistência passa pela API REST em Flask. Cada operação do site (listar imóveis, enviar contato, responder no chat) vira uma rota que executa SQL com psycopg2 e devolve JSON. Os dados de conexão ficam em variáveis de ambiente, nunca no código.

Cardinalidades

Relacionamento Cardinalidade Regra de negócio
cidades → bairros 1 : N Uma cidade tem vários bairros; cada bairro pertence a exatamente uma cidade.
bairros → imoveis 1 : N Um bairro pode ter vários imóveis; cada imóvel está em um único bairro.
tipos_imoveis → imoveis 1 : N Um tipo classifica vários imóveis; cada imóvel tem um único tipo.
imoveis → contatos 1 : N Um imóvel pode receber vários contatos; cada contato aponta para no máximo um imóvel (ou nenhum).

Restrições de integridade

As regras ficam no próprio banco (não só no Flask): é a última linha de defesa contra dados inválidos, mesmo que alguém escreva direto no SQL.

Tabela Restrição O que garante
cidades UNIQUE (nome, uf) Não existem duas cidades iguais no mesmo estado.
cidades CHECK uf ~ '^[A-Z]{2}$' UF sempre com 2 letras maiúsculas.
bairros FK cidade_id → cidades (RESTRICT) Não exclui uma cidade que ainda tenha bairros.
bairros UNIQUE (nome, cidade_id) O mesmo nome de bairro pode existir em cidades diferentes.
tipos_imoveis UNIQUE (nome) O nome do tipo não se repete.
imoveis UNIQUE (codigo) Cada imóvel tem um código único (CV-001, CV-002...).
imoveis FK tipo_id, bairro_id (RESTRICT) Todo imóvel aponta para um tipo e um bairro válidos.
imoveis CHECK finalidade IN ('venda','aluguel') Só aceita as duas finalidades previstas.
imoveis CHECK status IN (...) Status limitado a disponivel, reservado, vendido ou alugado.
imoveis CHECK preco > 0, area_m2 > 0, quartos >= 0... Números coerentes; sem preço ou área negativos.
imoveis CHECK tamanho mínimo de titulo e descricao Evita cadastro com texto vazio ou de uma letra.
contatos FK imovel_id → imoveis (SET NULL) Excluir um imóvel não apaga o histórico de contatos.
contatos CHECK de formato de email e telefone E-mail com @ e domínio; telefone com 10 a 13 dígitos.
contatos CHECK tipo_interesse e status IN (...) Interesse e status só com valores controlados.

Consultas SQL da apresentação

Cinco consultas para rodar no SQL Editor do Neon, uma por vez. Cada uma demonstra um recurso diferente: JOIN, agregação, CASE, AVG e window function. Use o botão Copiar e cole direto no editor.

1

Contatos recebidos + imóvel de interesse + localização

Mostra o LEFT JOIN: mesmo o contato que não apontou um imóvel aparece (com COALESCE preenchendo os vazios). 

SELECT c.id,
       c.nome,
       c.email,
       c.tipo_interesse,
       c.status,
       COALESCE(i.codigo, '—')                 AS codigo_imovel,
       COALESCE(i.titulo, 'Não informado')     AS imovel,
       COALESCE(b.nome || ' / ' || ci.uf, '—') AS localizacao,
       c.criado_em
  FROM contatos c
  LEFT JOIN imoveis  i  ON i.id = c.imovel_id
  LEFT JOIN bairros  b  ON b.id = i.bairro_id
  LEFT JOIN cidades  ci ON ci.id = b.cidade_id
 ORDER BY c.criado_em DESC;
2

Contatos por tipo de interesse (com percentual)

GROUP BY com window function para calcular, em cada linha, o percentual sobre o total. 

SELECT tipo_interesse,
       COUNT(*)                                           AS total,
       ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (), 1) AS percentual
  FROM contatos
 GROUP BY tipo_interesse
 ORDER BY total DESC;
3

Imóveis à venda por faixa de preço

CASE WHEN cria as faixas e o GROUP BY usa a própria expressão como critério. 

SELECT CASE
         WHEN preco < 500000  THEN 'Até R$ 500 mil'
         WHEN preco < 1000000 THEN 'R$ 500 mil a R$ 1 milhão'
         ELSE                      'Acima de R$ 1 milhão'
       END      AS faixa,
       COUNT(*) AS quantidade
  FROM imoveis
 WHERE status = 'disponivel'
   AND finalidade = 'venda'
 GROUP BY faixa
 ORDER BY MIN(preco);
4

Preço médio por tipo de imóvel e finalidade

JOIN com tipos_imoveis e funções de agregação (AVG, MIN, MAX). 

SELECT t.nome              AS tipo,
       i.finalidade,
       COUNT(*)            AS quantidade,
       ROUND(AVG(i.preco), 2) AS preco_medio,
       MIN(i.preco)        AS menor_preco,
       MAX(i.preco)        AS maior_preco
  FROM imoveis i
  JOIN tipos_imoveis t ON t.id = i.tipo_id
 GROUP BY t.nome, i.finalidade
 ORDER BY t.nome, i.finalidade;
5

Top 5 bairros por imóveis e ticket médio

LEFT JOIN mantém os bairros ainda sem imóvel e o ORDER BY + LIMIT monta o ranking. 

SELECT b.nome      AS bairro,
       c.nome      AS cidade,
       c.uf,
       COUNT(i.id) AS imoveis,
       ROUND(AVG(i.preco), 2) AS ticket_medio
  FROM bairros b
  JOIN cidades c      ON c.id = b.cidade_id
  LEFT JOIN imoveis i ON i.bairro_id = b.id
 GROUP BY b.id, b.nome, c.nome, c.uf
 ORDER BY imoveis DESC, ticket_medio DESC
 LIMIT 5;
